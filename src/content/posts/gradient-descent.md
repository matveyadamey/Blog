## Введение

Всем привет! Сегодня мы обсудим градиентный спуск — один из ключевых алгоритмов в машинном обучении и оптимизации. Он используется для поиска локального минимума функции потерь путём итеративного движения в направлении, противоположном градиенту функции.
В машинном обучении он применяется для уменьшения ошибки модели - ее обучения.
Чтобы было понятно, что мы вообще оптимизируем, рассмотрим применение этого алгоритма на примере линейной регрессии.

## Коротенько про линейную регрессию

**Линейная регрессия**— Это простой и популярный метод машинного обучения для решения задач регрессии (предсказания числового значения).

Алгоритм находит прямую линию (в случае одной переменной) или гиперплоскость (в многомерном случае), которая наилучшим образом описывает зависимость между признаками (входами) и целевой переменной (выходом).

![иллюстрация](https://i5.imageban.ru/out/2025/08/23/f15ef4e35e45a40c93d6d1e47974189e.png)

**Уравнение линейной регрессии**:

$$y=w_0​+w_1​x_1​+w_2​x_2​+⋯+w_n​x_n​$$

где:
- y — предсказываемое значение,
- xi​ — входные признаки,
- wi​ — веса (коэффициенты),
- w0​ — смещение (intercept),


Алгоритм подбирает веса w , чтобы минимизировать **среднеквадратичную ошибку (MSE) **между предсказаниями и реальными значениями:

 Формула ошибки (функция потерь):

$$L(\mathbf{w}) = \frac{1}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)^2 = \frac{1}{n} \sum_{i=1}^{n} (y_i - \mathbf{w}^T \mathbf{x}_i)^2$$

где:

- n - количество наблюдений
- $y_i$ - правильный ответ на текущем наблюдении
- $\hat{y}_i$ - ответ модели

В матричной форме:

$$L(\mathbf{w}) = (\mathbf{y} - \mathbf{Xw})^T (\mathbf{y} - \mathbf{Xw})$$

(здесь мы временно игнорируем множитель 1/n, так как он не влияет на точку минимума)

2. Раскроем квадрат:

$$L(\mathbf{w}) = \mathbf{y}^T \mathbf{y} - 2\mathbf{w}^T \mathbf{X}^T \mathbf{y} + \mathbf{w}^T \mathbf{X}^T \mathbf{Xw}$$

3. Берём производную по w:

$$\frac{\partial L}{\partial \mathbf{w}} = -2\mathbf{X}^T \mathbf{y} + 2\mathbf{X}^T \mathbf{Xw}$$

4. Приравниваем производную к нулю (условие минимума) и делим на 2:

$$\mathbf{X}^T \mathbf{Xw} = \mathbf{X}^T \mathbf{y}$$

5. Решаем относительно w:

$$\mathbf{w} = (\mathbf{X}^T \mathbf{X})^{-1} \mathbf{X}^T \mathbf{y}$$

Получили **аналитическое решение **линейной регрессии.

## Проблема аналитического решения

### Вырожденность

Обратная матрица $ (\mathbf{X}^T\mathbf{X})^{-1}$ существует только если $\mathbf{X}^T\mathbf{X}$ невырождена, в противном случае алгоритм просто не сработает.

Вырожденной матрица может быть если:
- Признаки линейно зависимы (например, один признак — сумма двух других)

Число признаков d больше числа объектов n (при nn матрица\mathbf{X}^T\mathbf{X}будет иметь ранг ≤n<d , следовательно — вырождена)
В данных есть дублирующие столбцы
Даже если матрица почти вырождена, это может привести к проблеме с вычислительной устойчивостью - большой чувствительности решения к малым изменениям в данных.

На практике это можно либо отловить на этапе предварительного анализа, либо исправить использованием регуляризации (об этом подробнее когда-нибудь)

![Сравнение весов до и после применения регуляризации](b98639ccbbd6e4ceb65989aad1126ca1.png)

При корреляции между двумя признаками около 0.99 разброс весов на нескольких запусках без регуляризации очень высок.

### Плохая асимптотика
При большом числе признаков вычисление обратной матрицы дорого
Обращение матрицы требует O(d^3) операций, где d - количество признаков
Умножение матриц — O(nd^2), n - число наблюдений
Подробнее вопрос освещен ![тут](https://en.wikipedia.org/wiki/Computational_complexity_of_mathematical_operations)

При большом числе признаков d (например, d>10^5) вычисление обратной матрицы становится очень дорогим.

Если d=10^5 , то d^3=10^15 операций — это непрактично даже на мощных компьютерах. 

![Рост времени обучения с увеличением числа признаков](https://i7.imageban.ru/out/2025/08/23/6006de5e9ff7857e829512182dcca67b.png)

График построен при 15000 строк, чтобы исключить влияние вырожденности.

Существуют [способы оптимизации алгоритма обращения матрицы](https://en.wikipedia.org/wiki/Invertible_matrix#Methods_of_matrix_inversion), но кардинальной разницы они не приносят

![](https://i4.imageban.ru/out/2025/08/23/63826f1a10c571fe2bb3f56b054ae62b.png)

## Переход к градиентному спуску. Суть алгоритма

На помощь приходят численные методы. 
Главная идея - лучше сойтись в локальный минимум, чем не сойтись никуда.
В этом и состоит суть метода градиентного спуска - мы ищем не глобальный минимум функции, а локальный, что сделать куда проще (в большинстве случаев только это и возможно).
Представим ситуацию. 

Вы находитесь на вершине горы и вам необходимо спустится вниз. Вокруг туман, ничего не видно. Как выбрать маршрут? 

Интуиция подсказывает: чтобы спустится как можно быстрее, надо идти туда, где склон круче всего. 

Как математически определить крутизну склона? На плоскости это просто угол наклона касательной - производная. Если по каждому направлению крутизна определяется производной, то что такое крутизна по всем направлениям? Понять поможет иллюстрация:

![Градиент функции](https://i7.imageban.ru/out/2025/08/23/366968afabc1b2bcf77e3e5d32c6a07b.jpg)

Ответ - это градиент - вектор, координатами которого являются частные производные. Т.к. функция, которую мы оптимизируем - функция потерь, то производные логично берутся по весам модели.

Т.к. производная показывает скорость РОСТА функции, а нам нужно убывание, идти будем в противоположном градиенту направлении.

Тогда первый шаг нашего алгоритма, это понять в какой точке мы находимся и "нащупать наиболее крутой склон" - найти градиент в этой точке. 
Для примера возьмем функцию f(x) = x ^ 2. Ее производная - 2x.

```python
def f(x):
    return x ** 2
def grad_f(x):
    return 2 * x

```

Теперь надо выбрать точку старта (как?). Пока что возьмем на рандом, x = 3. 
Производная в этой точке 2 * 3 = 6 -> функция в окрестности этой точки растет.
Т.е. если мы еще немного увеличим аргумент, то и значение функции увеличится. Нам же нужно обратное. Поэтому будем идти в противоположную сторону.

Что делать когда поняли куда идти? Собственно начать идти!

Второй шаг - сделать шаг (lol) в направлении, противоположном направлению градиента. Остается вопрос - какой длины этот шаг? обсудим его чуть позднее

```python
x -= grad_f(x)
print(x, f(x))

```

И вот по идее мы стали на шаг ближе к минимуму.
Но есть одно но - если посмотреть на значение функции, видно, что мы "перепрыгнули" экстремум!

![Слишком большой шаг](b98639ccbbd6e4ceb65989aad1126ca1.png)

Т.е. наш шаг был слишком велик. Уменьшим его например до 0.8. 

![А теперь шаг хороший](https://i7.imageban.ru/out/2025/08/23/4c3eff3d0d782531cf4cbca64f6111fb.png)

Ура! Мы вышли из цикла.
Повторяем процесс, пока не дойдем до "низины".

Снова вопрос - как понять, что мы достигли места назначения? 
Ответ казалось бы очевиден - градиент (по аналогии с производной) в точке экстремума равен нулю. 
Но вспомним ситуацию с шагом: если он недостаточно мал, то алгоритм будет бесконечно скакать вокруг экстремума и никогда не завершит работу. Поэтому давайте считать, что нам нужен не сам экстремум, а просто быть достаточно недалеко. И когда алгоритм будет попадать в заданную окрестность экстремума, он будет завершать работу.

```python
step = 0.8
eps = 0.1 #окрестность
while True:
    x -= step * grad_f(x)
    print(x, f(x))
    if -eps <= f(x) <= eps:
        break

```

![Условие остановки](https://i2.imageban.ru/out/2025/08/23/0519ce2a61a3ffae13fcc73e0013c62b.png)

Для демонстрации задал окрестность +-1 и стартовую точку 8.
Как видно, как только значение функции стало приближаться к нулю, алгоритм остановился.

Итак, алгоритм коротко:
1. выбрать точку старта
2. рассчитать градиент в ней
3. сделать шаг в направлении антиградиента
4. повторять шаги 2-3, пока не выполнится условие остановки

## Обучение линейной регрессии градиентным спуском

Теперь возьмем в качестве функции функцию потерь линейной регрессии и попробуем обучить ее.
К счастью, градиент mse мы можем найти в явном виде.

```python
# Данные
X = np.array([[1, 1], [1, 2], [1, 3]])
y = np.array([1, 2, 3])
# Параметры
w = np.array([0.0, 0.0])
step = 0.01
eps = 0.001
# Функция потерь и градиент
def loss():
 return np.mean((X @ w - y)**2)
def grad():
 return 2 * X.T @ (X @ w - y) / len(y)
# Градиентный спуск
while True:
 w -= step * grad()
 print(w, loss())
 if abs(loss()) < eps:
 break

```

![Предсказания модели](https://i4.imageban.ru/out/2025/08/23/423d7ef3ca88192fcc94d4f9998097c6.png)

## Learning rate

Поговорим подробнее о шаге градиентного спуска, по-английски - learning rate.

Почему важно правильно подобрать шаг?
Как мы уже выяснили, если шаг будет слишком большим, алгоритм будет перепрыгивать экстремум или даже расходится.
Ну а если он будет слишком маленьким, то точность конечно будет хорошая, но вот скорость сильно упадет. Также есть вероятность застрять в небольшом локальном минимуме.

![Влияние lr на сходимость](https://i7.imageban.ru/out/2025/08/23/220ceeed243f1d2e3945e4cccd498ad0.png)

В принципе, можно просто перебором подобрать неплохой learning rate вручную. 
А можно сделать так, чтобы он менялся в процессе работы алгоритма.
Такие алгоритмы называют learning rate sheduler.
Вот основные:
1.**Step Decay**

Шаг уменьшается в фиксированные моменты (в примере - каждую итерацию).

```python
def step_lr_scheduler(epoch, lr_init, gamma=0.5, step_size=1):
 return lr_init * (gamma ** (epoch // step_size))

```

**lr_init**- начальный learning rate

**step_size**- количество итераций, раз в которое мы меняем lr

**gamma**- некий множитель

![Step decay](https://i2.imageban.ru/out/2025/08/23/39a8cc8b3afca2417b3b6090434b5105.png)

2.**Exponential Decay**

Непрерывное экспоненциальное уменьшение.

```python
def exp_lr_scheduler(epoch, lr_init, gamma=0.95):
 return lr_init * (gamma ** epoch)

```

![Exponential decay](https://i6.imageban.ru/out/2025/08/23/2b127ab4bc1c2154a0fd882ba772bb1d.png)

**3. ReduceLROnPlateau**

Уменьшает шаг, когда функция перестаёт убывать

```python
def reduce_lr_on_plateau(current_lr, losses, factor=0.5, patience=5, min_lr=1e-6, threshold=1e-4):
    if len(losses) > patience:
        # Минимальный loss среди последних (patience + 1) значений, кроме последнего
        recent_min = min(losses[-patience-1:-1])
        current_loss = losses[-1]
        # Если улучшения нет — снижаем LR
        if current_loss >= recent_min - threshold:
            current_lr = max(current_lr * factor, min_lr)
    return current_lr

```

**current_lr**: текущий learning rate

**losses:**история значений функции

**factor**: множитель уменьшения (например, 0.5)

**patience**: количество эпох без улучшения

**min_lr**: минимальный допустимый lr

**threshold**: минимальное значимое улучшение (абсолютное)

![ReduceLROnPlateau](https://i4.imageban.ru/out/2025/08/23/b81f02c1252b7805c49592dc3edcafcd.png)

Таких методов очень много, можно ознакомится с ними [тут](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.LRScheduler.html)

В более сложных модификациях градиентного спуска есть более интересные способы, например Adam **адаптивно регулирует скорость обучения для каждого параметра**. Вместо того чтобы использовать единую фиксированную скорость обучения для всех весов в сети, Adam рассчитывает индивидуальную скорость, которая регулируется по мере обучения.

## Выбор стартовой точки

Как я уже упомянул, градиентный спуск находит локальные минимумы. Но как все же найти если не глобальный, то хотя бы более близкий к нему? Давайте разберемся, почему мы попадаем в локальный минимум. Одна из причин - маленький шаг, ее мы уже обсудили.

А вот иллюстрация второй:

![Проблема выбора стартовой точки](6e526e30fa6e94455a90f4d38f7bdd22.png)

Как можно заметить, от стартовой точки сильно зависит куда алгоритм по итогу сойдется. Поэтому, чтобы повысить вероятность попасть в "хороший" экстремум, можно перебрать несколько стартовых точек. Такой алгоритм называется **мульти-старт**.

## Проблемы алгоритма

У классического градиентного спуска есть много проблем, некоторые мы с вами уже обсудили:

- **Медленная сходимость**— особенно на овражных или плохо обусловленных функциях.
- **Чувствительность к скорости обучения**— слишком большой шаг вызывает расходимость, слишком малый — замедляет обучение.
- **Затруднения с локальными минимумами и седловыми точками**— может застрять, несмотря на нулевой градиент.
- **Высокая вычислительная стоимость**— на каждой итерации требуется обработать **все обучающие данные**, что непрактично при больших объёмах.

Отсюда возникает необходимость в стохастическом градиентном спуске (SGD) или мини-батч версии.

## Стохастический градиентный спуск

Раз считать градиент по всей выборке долго, давайте попробуем считать его либо по малой части (батчу), либо вообще по одному объекту.
Когда мы считаем градиент по одному объекту такая модификация называется **стохастическим градиентным спуском**

```python
for epoch in range(epochs):
    epoch_loss = 0.0
    # Перемешиваем данные каждую эпоху
    indices = np.random.permutation(n_samples)
    for i in indices:
        # Берём один пример
        x_i = X[i]
        y_i = y[i]
        # Предсказание
        pred = w * x_i + b
        # Вычисляем градиенты (частные производные по MSE)
        dw = 2 * (pred - y_i) * x_i  # градиент по w
        db = 2 * (pred - y_i)        # градиент по b
        # Обновляем параметры
        w -= learning_rate * dw
        b -= learning_rate * db

```

![График функции потерь SGD](https://i4.imageban.ru/out/2025/08/23/898cc9046768fb2642e375144e86f745.png)

Learning rate = 0.17
Как видим, сгд довольно нестабилен. Однако уменьшение lr улучшает ситуацию.

![SGD с маленьким lr](https://i6.imageban.ru/out/2025/08/23/7bc95466064e45845d9406bd21b142dc.png)

Learning rate = 0.1

Также стабилизировать помогает расчет не по одному объекту, а по мини-батчу:

```python
batch_size = 16
# Mini-batch SGD
for epoch in range(epochs):
 epoch_loss = 0.0
 # Перемешиваем данные
 indices = np.random.permutation(n_samples)
 # Разбиваем на батчи
 for start in range(0, n_samples, batch_size):
 end = min(start + batch_size, n_samples)
 batch_indices = indices[start:end]
 X_batch = X[batch_indices]
 y_batch = y[batch_indices]
 # Предсказания для батча
 preds = w * X_batch + b
 errors = preds - y_batch
 # Вычисляем средние градиенты по батчу
 dw = 2 * np.mean(errors * X_batch) # градиент по w
 db = 2 * np.mean(errors) # градиент по b
 # Обновляем параметры
 w -= learning_rate * dw
 b -= learning_rate * db

```

![Mini-batch SGD](https://i5.imageban.ru/out/2025/08/23/cb0bdd12e804bef94ced32fb16ad4bef.png)

Если нестабильность сохраняется, а размер батча увеличивать нельзя, можно попробовать следующую идею:
начать с маленького размера батча (или вообще с одного объекта) и по мере обучения его увеличивать по какой-то монотонно возрастающей функции.

```python
def get_batch_size(epoch, total_epochs, initial=1, max_size=32):
 return max(1, int(initial + (max_size - initial) * (epoch / total_epochs)))
# Инициализация
w, b = 0.0, 0.0
learning_rate = 0.05
epochs = 100
for epoch in range(epochs):
 current_batch_size = get_batch_size(epoch, epochs, initial=1, max_size=32)
 indices = np.random.permutation(n_samples)
 for start in range(0, n_samples, current_batch_size):
 end = min(start + current_batch_size, n_samples)
 batch_idx = indices[start:end]
 X_b, y_b = X[batch_idx], y[batch_idx]
 pred = w * X_b + b
 error = pred - y_b
 dw = 2 * np.mean(error * X_b)
 db = 2 * np.mean(error)
 w -= learning_rate * dw
 b -= learning_rate * db

```
